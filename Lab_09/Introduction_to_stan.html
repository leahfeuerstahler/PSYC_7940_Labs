rstan and brms

  • rstan and brms are both R interfaces to the command-line program stan.

  • Compared to rstan, brms is more user-friendly. Instead, rstan is more flexible and can fit more complex models than brms.

  • Today we will learn how to use rstan by writing stan code directly. Proficiency in stan won’t be tested in this course, but it may be helpful if you want to do research in practice.

  • stan is very flexible/general, which makes it useful for many varied models. Because it does not make any assumptions about your model, you will need to provide more information than usual (including explicitly stated the sample size).

stan Files

For any stan model, we need to add information to these 3 blocks:

  • data
  • parameter
  • model

We’ll fill them one by one for the weather data.

library(tidyverse)
library(rstan)
temps <- read_csv("weather.csv")
temps <- temps %>% mutate(YEAR = YEAR - 1918)
temps %>% glimpse

data Block

Take the simple linear regression model (Avg_High_Temp ~ YEAR). In the data block, we need to specify the variables we are using in the model, and the length (sample size) of each variable.

  • vector[107] Avg_High_Temp; means that we define a vector of length 107 with the name Avg_High_Temp

  • We use this same pattern for the variable YEAR.

  • Variable names should match those in the data.

  • In the stan language, comments follow //

data{ // this is the data block
  vector[107] Avg_High_Temp;
  vector[107] YEAR;
}

Don’t forget the semi-colon!

parameter Block

In the parameters block, we specify parameters that we name however we like. Here, we use:

  • a for the intercept

  • b for the slope

  • sigma for the residual variance

We specify these as real variables because we want to estimate these parameters on the entire real number line.

parameters{
    real a;
    real b;
    real<lower = 0> sigma;
}
  • <lower = 0> means to set a lower bound of 0 on the sigma parameter.

model Block

In the model block, we will specify both the priors and the model formula:

model{
  a ~ normal(45, 5);
  b ~ normal(0, 5);
  sigma ~ lognormal(0, 5);
  Avg_High_Temp ~ normal(a + b*YEAR, sigma);
}

After entering these three blocks in your file, save the file to your current working directory as weather.stan.

Unlike brms, stan does not remove NA values for us. If the data set is not complete, stan returns a warning message and stops:

temps2 <- temps
temps2[1, 1] <- NA # set one observation to BA

Error in FUN(X[[i]], ...) : Stan does not support NA (in YEAR) in data

weather_mod <- "
data{
  vector[107] Avg_High_Temp;
  vector[107] YEAR;
}
parameters{
    real a;
    real b;
    real sigma;
}
model{
  a ~ normal(45, 5);
  b ~ normal(0, 5);
  sigma ~ lognormal(0, 5);
  Avg_High_Temp ~ normal(a + b*YEAR, sigma);
}
"

Running stan

We may prefer to include sample size as a variable rather than explicitly coding it in the model. We can do so by making the following modifications to the data block:

weather_mod2 <- "
data{
  int N; // sample size
  vector[N] Avg_High_Temp; // now of length N
  vector[N] YEAR; // now of length N
}
parameters{
    real a;
    real b;
    real sigma;
}
model{
  a ~ normal(45, 5);
  b ~ normal(0, 5);
  sigma ~ lognormal(0, 5);
  Avg_High_Temp ~ normal(a + b*YEAR, sigma);
}
"

Running stan

temps_list <- list(N = 107,

                   YEAR = temps$YEAR)
m3 <- stan(model_code = weather_mod2, data = temps_list)

The stan package is not designed to calculate any further summary information for us. Instead, we must work with the sampled parameters directly. Below, we plot a 95% credible band around the best-fit lines.

  1. Create an empty matrix with one column for each year and one row for each posterior draw.
preds <- matrix(NA, nrow = 4000, ncol = 107)
  1. Loop through each year and save the predictions at each year.
for(i in 1:107){
  preds[, i] <- post_samps$a + post_samps$b * temps$YEAR[i]
}

testprep_mod <-"data {
  real math[1000];
  int raceEthnicityInt[1000];
}
parameters {
  real<lower=0> sigma;
  real a[5]; // define five intercept parameters
}
model {
  real mu[1000];
  for (i in 1:1000) mu[i] = a[raceEthnicityInt[i]];  // refer to indices
  math ~ normal(mu, sigma);
  a ~ normal(0, 1);
  sigma ~ exponential(1);
}"

Index Variables

Several tips for categorical variable coding:

  • In the data block, define int (integer) for categorical variables. The categorical variables should be transformed to numeric type in your data set.
  • In the parameters block, specify the number of levels for the parameters of categorical variables.
  • In the model block, create a variable mu to summarize the average prediction for each data point.
